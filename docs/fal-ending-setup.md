# falのAPIキーを登録する手順

2026-09-14。[実装計画](../specs/ending-video/plan.md)に対応する設定手順。GitHubへのキー登録と、コードの公開更新は別の作業。キーの登録だけでは稼働中のゲームに動画機能は反映されない。

## 何を設定するのか

falのAPIキーは、公開サーバーが動画生成サービスを利用するための秘密の文字列。GitHubで保存し、公開更新の際にサーバーへ渡す。参加者のスマホやWeb画面には渡さない。

このリポジトリには、以前から`development`と`judging`という名前の公開用workflow設定がある。今回の動画機能のために新設した環境ではない。実際にどちらの環境を用意・使用しているかは、この設定ファイルだけでは判断できない。

**キーは運営が使用している環境へ登録すればよい。`judging`を新しく作ったり、利用したりすることは今回の必須作業ではない。** `judging`は運営側が用意する審査用サーバーの設定名で、審査員本人がキーを登録するという意味ではない。GitHub **Environment** に登録すると既存のworkflowに沿う。Repository secretも利用できるが、以下はEnvironmentへ登録する場合の手順。

## 1. falでキーを用意する

[falのダッシュボード](https://fal.ai/dashboard/keys)で、このアプリに使用するAPIキーを発行するか、管理者から用意済みのキーを受け取る。アカウントの利用権限や残高は運営が確認する。

キーの実値をこのチャットに貼ったり、Gitに追加したりしない。API側で使う環境変数名は`FAL_KEY`。[fal公式API手順](https://fal.ai/models/minimax/h3-max-turbo/image-to-video/api)

## 2. GitHubに登録する

1. GitHubでこのプロジェクトのリポジトリを開く。
2. 上部の **Settings** を開く。
3. 左のメニューから **Environments** を開く。
4. 使用している環境（開発環境なら **development**）を選ぶ。
5. **Environment secrets** の **Add secret** を押す。
6. **Name** に `FAL_KEY`、**Value**（秘密値の入力欄）にfalのキーを入力する。
7. **Add secret** で保存する。
8. 運営が`judging`も使用すると決めている場合だけ、その環境へも同じ手順で登録する。未使用なら不要。

SettingsやEnvironmentsの設定権限がない場合は、リポジトリ管理者にこの手順を渡す。保存後に一覧で確認するのは`FAL_KEY`という名前であり、秘密値を表示して確認する必要はない。[GitHub公式手順](https://docs.github.com/en/actions/how-tos/write-workflows/choose-what-workflows-do/use-secrets)

## 3. Webサーバーへ変更を反映するときの有効化設定

同じEnvironmentの **Environment variables** に以下を設定する。これらは秘密値ではないのでVariables側に追加する。

| 名前 | 値 | 意味 |
| --- | --- | --- |
| ENDING_VIDEO_ENABLED | true | プレイ終了時の動画生成を有効にする |
| AI_GLOBAL_VIDEO_ATTEMPTS | 運営が決めた整数 | このサーバープロセスで送信できる動画の最大回数 |
| RESULT_TTL_SECONDS | 600 | 終了後の結果を最大10分保持する |
| ENDING_JOB_TIMEOUT_SECONDS | 省略時480 | 動画準備と生成の締切（秒）。60〜540 |
| ENDING_CONCURRENT | 省略時2 | 同時処理する動画数。1〜2 |

`AI_GLOBAL_VIDEO_ATTEMPTS`は1〜1,000の整数。たとえば10に設定した場合、10回送信した時点で以降の動画生成を止める。10は設定方法の例であり、予算として合意済みの値ではない。回数カウンターはサーバー再起動で戻るため、サービス全期間の金額上限にはならない。送信が受理されたか不明な通信失敗も回数を消費し、自動で再送しない。

`ENDING_VIDEO_ENABLED`は省略時`false`。`true`にする場合はキーと動画回数の両方が必須で、不足や不正な設定があれば公開処理またはサーバー起動がエラーになる。`RESULT_TTL_SECONDS`は動画締切より60秒以上長く、最大600秒にする。有効時に省略すると600秒、無効時は従来の300秒になる。すでに300が明示されている環境では、600へ変更する。

画像の生成・検査と脚本には、既存のOpenAI設定・予算も必要。falだけの設定で画像や脚本まで生成できるわけではない。

## 4. 公開更新と確認

Secretを保存しただけでは、稼働中のサーバーは更新されない。`deploy-dev.yml` / `deploy-judging.yml`と配信スクリプトが、動画機能を含むコードの公開更新で`FAL_KEY`と動画設定をサーバーへ渡す。キーはDockerのbuildやWebの配布物へ渡さない。

ここでいう「公開更新」「リリース」は、運営が使うWebサーバーへ変更したコードを配信すること。この説明やキー登録が、配信を実行する承認になるわけではない。

既存の設定では **mainへの反映が開発環境の公開更新を起動する**。通常の開発PR先はdevelop。Secret登録の確認だけを目的にmainへpushしない。`judging`を利用する場合はmainのworkflowから手動配信する。実際の配信先と実施タイミングは運営が決める。詳細は[公開手順](hosting.md)。

公開後は実際のプレイで、準備中・生成中表示→手動の動画再生→プレイ固有の物語を確認する。「結果を見る」を選ぶと動画終了を待たず物語を読める。3個解除のhappyだけでなく、2個解除で時間切れ・行動回数切れのnormal、0〜1個解除のbadも確認する。結末の物語は舞台の固定文ではなく、そのプレイの提示済み伏線と確定した行動から作られる。実falの利用と画像生成には料金が発生する。

## ローカルで試す場合

GitHubのSecretは手元のPCへ自動配布されない。既存の`.env.local`に次の設定を追加する。ファイル全体を置き換えず、他の設定を保持する。ルート`.env`は使用しない。

```dotenv
FAL_KEY=ここを手元で実際のキーに置き換える
ENDING_VIDEO_ENABLED=true
AI_GLOBAL_VIDEO_ATTEMPTS=100
RESULT_TTL_SECONDS=600
```

今回の試遊では100回を使用する。コードへ実値を転記せず、`.env.local`をGitへ追加しない。設定変更後はローカルサーバーを再起動する。mockモードは実fal・実OpenAIを呼ばず、実動画の成功確認には使わない。

`npm.cmd run play:mobile`もこのPCの`.env.local`を使用する。GitHubで100回にしても、ローカルが1回のままならローカル試遊は1回で上限に達する。起動時の「エンディング動画: 有効（…100回まで）」を確認する。

ゲーム終了時点で完成している場面画像があれば、それを使って動画制作に進む。最後の場面画像や全画像の完成は待たない。古い画像を使う場合も結末・解除数・確定行動は終了時の内容を反映する。完成済みの場面画像が1枚もない場合は素材不足となる。終了前の音声の文字起こしを受け取る既存の猶予（最大12秒）は残るが、その間に完成した画像を動画の素材に追加することはない。

失敗した場合は、画面の理由と「不具合報告用の情報」のコードを確認する。例えば`ENDING_BUDGET_EXHAUSTED`は動画回数上限、`ENDING_STORY_...`は物語・演出、`ENDING_START_FRAME_...`は開始画像、`ENDING_END_INSPECTION_...`は終了画像の内容検査、`ENDING_VIDEO_SUBMIT_...`はfalへの依頼を示す。PCのターミナルにも`ending_failed_...`として同じコードを出す。キー・画像・会話・上流応答本文はこのログに含めない。失敗した既存プレイの動画を再送する機能はないため、変更を確認するには再起動後に新しいプレイを行う。

## 費用と表示の制約

768P・15秒の動画部分は通常価格で0.60 USDが目安。2026-09-14確認時のfal公式ページには、同日終了の割引中は0.15 USDと記載されている。適用価格は利用前に[fal公式料金](https://fal.ai/models/minimax/h3-max-turbo/image-to-video)で再確認する。開始・終了画像、検査、脚本の料金は別途必要。

生成が遅い場合でも通話は終了し、動画を待つ間に結果と履歴を閲覧できる。既定では動画準備は最大8分、結果保持は終了から最大10分。再読み込みは同じ動画の状態を確認するだけで、再生成しない。容量上限やサーバー再起動でも動画は失われる。失敗した動画を自動で再送して追加課金しない。

実fal・画像編集・実スマホでの音声付き動画再生、生成内容と終了文字の品質、同時5人の負荷は、課金なしの自動テストとは別に確認する。この手順書は実生成や公開の成功記録ではない。
