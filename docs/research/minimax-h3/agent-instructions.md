# H3生成担当エージェントへの指示

このファイルはプロンプトの作成・見直し用。既存プロジェクトや特定CLIに依存しない。[調査と出典](README.md)、[記入例](prompt-templates.md) と併用する。

今回の用途は顔をあまり映さず、台詞・感情表現を前提にしない。[演出とカメラワーク](cinematography.md)を優先し、手元・足元・背面・物・空間の構図、移動、カット、情報を見せる順序で構成する。発話・ナレーション・口パクは追加しない。

## 1. 最初に制作条件を分離する

次を短い制作メモにする。不明な項目を承認済みの値として埋めない。演出上の軽微な仮定は明記して下書きを進めてよい。

```yaml
intent: 観客に最後に何が伝われば成功か
provider_and_model: 提供先と正確なモデル・経路
input_mode: text / first-frame / first-last-frame / last-frame / references
duration_seconds: 未確定なら未確定
aspect_ratio_and_resolution: 未確定なら未確定
references:
  - file: 実際の素材識別子
    api_slot: 入力フィールドとリスト内の順番
    role: 外見 / 衣装 / 背景 / 構図 / 動作 / カメラ / 声質 / 音源コピー
    retain: 維持する特徴
    change: 変更してよい特徴
audio: 台詞・語りなし。環境音 / 効果音 / 音楽それぞれの要否
must_show: 必須の動作・画面情報
must_preserve: 変更しない要素
allowed_changes: 今回変更する要素
```

モデル名だけで入力仕様を推定しない。画像・動画・音声は利用可能な閲覧手段で内容を確認し、確認できない部分を申告する。ファイル名から外見や動作を創作しない。

## 2. 入力モードを決めてから文章を書く

| 入力 | 設計で答える問い |
|---|---|
| テキストのみ | 最初に何がどこに見えるか、そこから何が起きるか |
| 開始画像 | その姿勢・配置から次にどの動きが始まるか |
| 開始・終了画像 | 両端の差を、途中のどの動作やカメラ変化でつなぐか |
| 終了画像のみ | その終わり方に至る自然な直前状態は何か |
| 複数参照 | 各素材の何を、どの被写体・時点に使うか |

基本系と参照系の正式な出力構造は [公式スキル](https://github.com/MiniMax-AI/MiniMax-H3/blob/main/skills/h3-prompt-writing/SKILL.md) のモード分岐に従う。厳密な書き換え形式を要求される場合は、原典の該当ガイドを読み、フィールド名・順序・画像整合行を省略しない。下書き用テンプレートをそのまま正式形式と称さない。

## 3. 演出を観察できる出来事へ落とす

以下は本資料の作業上の推奨。比較検証済みのH3固有則ではない。

- 「感動的」「迫力がある」で止めず、手の動き、視線、物の状態、画面内の距離などに置き換える。
- 各場面を「開始状態 → 主な動作 → 見える結果」で書く。短い尺に入らない動作は、文章を詰め込む前に演出を減らす。
- 把持や接触が重要なら、どちらの手、接触箇所、支持される位置、離す順序まで書く。見えない内心や物理用語だけで解決しない。
- 同じ瞬間に固定カメラと周回、完全静止と全身運動などを要求しない。動作を段階化するか、優先する一方を選ぶ。
- 必須条件を先に確定し、装飾は残りの余裕に入れる。語数を増やすだけの形容詞や重複した禁止事項を削る。
- 参照にない裏面や隠れた部品の正確さが必要なら、その情報が不足していることを明示する。

## 4. 時間・カメラ・音を同期させる

公式基本形式では最初を `[Shot 1]`、後続カットを `[Shot 2] At 00:04.000, ...` のように指定する。カメラは移動の種類と必要な速さ・幅を書く。環境音と観客向け音楽を分離する。BGMなしは `non_diegetic_music: N/A`。環境音を残すなら `overall_soundscape` までN/Aにしない。[公式基本ガイド](https://huggingface.co/MiniMaxAI/MiniMax-H3/blob/main/docs/VIDEO_PROMPT_WRITING_GUIDE_base_en.md)

作業上は、動作の準備時間、反応までの間、最後の情報を読む時間を見積もる。タイムコードは生成への要求であり、フレーム精度での達成保証ではない。音楽の有無は依頼ごとに決め、無条件に追加・禁止しない。

## 5. 参照関係は対象と適用範囲まで書く

公式参照形式の `<Subject N>` は素材から取り出す人物・物・外見等、`<Picture N>` はフレーム等の基準、`<Video N>` は映像の構造等、`<Audio N>` は音源の役割を表す。`retention_analysis` には保持・一部保持・属性移植・弱い参考を区別して記す。映像内の音が自動でそのまま再利用されると仮定しない。[公式参照ガイド](https://huggingface.co/MiniMaxAI/MiniMax-H3/blob/main/docs/VIDEO_PROMPT_WRITING_GUIDE_ref_en.md)

APIへ変換するときは別に対応表を作る。例えばfalの `Image 1` と内部の `<Subject 1>` は同じ概念ではない。一枚から複数の対象を定義することもある。タグだけを書いて実ファイルが送られていない状態を避ける。

## 6. 出力する成果物

1. **制作メモ**: モード、条件、参照対応、未確定事項。
2. **プロンプト本文**: その経路で使用できる文字列。相談文・作業メモを混ぜない。
3. **整合確認**: 尺、画像との矛盾、参照番号、音、必須条件のチェック結果。
4. **検証状態**: 下書き／送信済み／回収済み／内容確認済み等を事実に沿って記す。

料金・解像度・本数・参照素材を含む外部生成の実行範囲は、利用者の承認内容に従う。この資料を読むことは送信や有料リトライの承認ではない。

## 7. 結果が外れたときの修正表

以下は原因を切り分けるための仮説。症状だけでモデル内部の原因を断定しない。

| 症状 | 最初に調べるもの | 次の修正案 |
|---|---|---|
| 動かない | 入力画像の状態と要求動作、展開後の文章 | 最初の動き出しと到達状態を具体化 |
| 人物・服・小物が変わる | 参照同士の競合、特徴の指定先 | 特徴ごとの参照元を一つに整理 |
| 物が瞬間移動する | 接触・移動・持ち替えの省略 | 中間動作を加えるか、一連の動作を短縮 |
| カメラが勝手に切り替わる | カット記述と移動記述の混在 | ワンショットか複数カットかを明確化 |
| 終了画像へ唐突に変化 | 終点との差と残り時間 | 動作の経路を修正。画像変更は別の変更として扱う |
| 音楽や台詞が不要なのに入る | 各音の要否、展開で加わった記述 | 必要な音を具体化し、不要な層を明記 |
| 編集で対象外も変わる | 変更対象と保持対象の曖昧さ | 対象範囲を明示。完全保持できたとは視聴前に報告しない |

比較では一度に変える主な要因を一つにする。モデル、入力素材、解像度、尺、seed、プロンプト展開条件も記録する。同じseedでの一致を保証せず、取得できた `expanded_prompt` は元の本文と分けて保存する。人による採用判定と、リクエスト成功を分ける。
