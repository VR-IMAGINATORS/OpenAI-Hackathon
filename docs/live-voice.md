# Liveの読み方・声・話速

## 今回の変更

- 音声専用の投影で「閂→かんぬき」「内扉→うちとびら」「引き輪→ひきわ」「反時計回り→はんとけいまわり」等を変換する。対象は `apps/local-server/live-speech.ts`。初期資料と後続の通知に適用し、画面・保存済み会話・判定用の原文は変更しない。まだ登場していない用語を辞書としてLiveへ送らない。
- Liveが公開事実から言葉を選ぶ構成を維持し、重複する説明・運用指示を整理。ヒントは意味を保って言い換え可能とし、語尾や三点リーダーを伸ばす演技を避ける。
- 導入から本編まで「自然に、聞き取れる範囲で早口」とだけ指定する。ユーザー試遊で速度改善が弱かったため、焦りの演技・独り言・敬体等の指定は撤回した。音声へ渡す資料から旧来の落ち着いた敬体の指定も除く。
- 時間通知の落ち着いた口調・気づいたような演技指定を除去。割り込み、委譲、結果確定、知識開示の制御は維持。声はgleamのままで指示だけを比較する。

## 声の設定

初期候補は `gleam`。速さや日本語の自然さが他の声より優れると実証した選択ではなく、試聴して調整するための候補。

ローカルは `.env.local` に `LIVE_VOICE=gleam` を指定できる。以前のAPI既定声へ戻して比較する場合は `LIVE_VOICE=marin`。再起動し、新しい音声セッションを開始する。ブラウザ再生速度を変える方式ではない。

公開環境は GitHub Environmentの `LIVE_VOICE` Variable を使用。未指定ならgleam。設定変更の反映にはデプロイと新しい音声セッションが必要。

## 実音声で比較する項目（未実施）

同じ端末・同じ場面で声だけを変え、導入／内扉の説明／行動結果／ヒントの録音を比較する。

1. 「閂」「内扉」「引き輪」等の読み間違い。
2. 本編に入ってから発話そのものが遅くならないか。応答開始までの待ち時間とは分ける。
3. 早口でも重要語が聞き取れるか。ヒントの語尾を引き伸ばさないか。
4. 「待って」「もう一度」の割り込みと、結果の重複・先走りがないか。

音声の改善・完全な誤読解消はコードテストでは保証できない。今回の自動検証は設定伝達、表記変換、文字数上限、既存ゲーム機能の回帰を対象とする。

## 公式資料（2026-09-16確認）

- [Prompting GPT-Live](https://developers.openai.com/api/docs/guides/live-prompting): 会話指示は短くし、話し方・言語・発音を指定。細かい業務処理はバックエンドへ置く。
- [Managing GPT-Live sessions](https://developers.openai.com/api/docs/guides/live-conversations): `audio.output.voice` はセッション作成時に指定。変更には新しいセッションが必要。
