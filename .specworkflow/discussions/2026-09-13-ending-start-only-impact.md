# 終了画像が再生成された問題の影響調査と修正

## 原因

前回はmedia.pyの比較試作経路だけを開始画像のみへ変更し、通常プレイのgame.pyが終了画像を要求したままだった。SKILL.mdとending.mdも「別版の例外」として追記し、Story.md・CLIのコマンド例・仕様には旧2画像制作が残った。文章だけ変更しても通常登録を完了できない構造だった。

## 調査範囲と対応

| 経路 | 影響と対応 |
|---|---|
| SKILL.md → Story.md → ending.md | 別版限定を廃止。新規・再開・別版とも開始画像1枚。終了画像とゲーム中の絵コンテは生成しない。固定3区間・大きな移動の必須化・文字禁止・動画前の結末本文提示を除去 |
| h3-cli.md / cli.md | 標準例からend-imageとattach-endingを除去。旧承認済み2画像runだけ互換扱い |
| game.py ending-packet | productionで入力枚数・絵コンテなし・確定表示ラベル・H3文字同時生成を明示。状態のスキーマ移行は不要 |
| game.py attach-video / receipt | nullを明示した開始画像のみの動画を通常登録可能に。開始画像・動画・承認・request IDの照合は維持。旧2画像runは登録終了画像と照合。動画登録後に新しく終了画像を付け足さない |
| media.py / generate_h3.py | 既存の任意終了画像対応を確認。省略時にアップロード・送信しないテストを維持。既承認runは変更しない |
| staging.py / spatial-staging.md | 開発用の任意経路へ限定。全面文字禁止を除き、任意タイトルと登場時刻を扱う。ゲームの標準制作では呼ばない |
| spec / plan / data-model / README / 制作設計 | 通常プレイまで含む契約と実装状況へ同期 |
| handoff / quality-design / cinema-rewrite | 旧調査・候補を履歴資料と明示し現行手順へ誘導。過去の実績や当時の入力を改ざんしない |
| H3研究の汎用I2V/R2V例 | H3一般の機能説明として保持。ゲーム手順ではない。文字ノウハウのstaging未改修記述は修正 |
| 初回・攻略結果画像のmedia.md | 文字を禁止するのはゲーム中画像の正しい制約なので維持。エンド動画とは別経路 |
| Web版 / 既存プレイ / runs | 会話スキルと独立。既存状態・写真・動画・承認を変更しない。Web版へエンディング制作を実装したとは扱わない |

## 確認

無課金テストでTrue/Normal/Badの新規live状態を作成し、終了画像なしの承認証跡・receiptを使って動画登録、表示ゲート、結果公開まで通す。動画はテスト用、ffprobeはスタブであり実動画生成の検証ではない。終了画像ハッシュ矛盾・欠落、開始画像改ざんを拒否し、状態が変化しないことを確認。旧2画像登録とmedia側の省略・承認改ざんテストも維持する。

別セッションでは更新後のSKILL.md・ending.mdを読み直し、ending-packetを現行CLIで再取得する。既に読んだ古い指示が会話文脈に残る場合は新しいセッションを使う。画像生成済みでも未承認なら開始画像のみで新しいprepareへ進める。承認・送信済みrunは入力を変更せず回収する。

今回は既存機能の不整合修正。SpecWorkflowツールは現在の公開一覧に存在せず、正式なワークフローや独立レビューを実行済みとは扱わない。
