# ゲームコアのブラッシュアップ
現状は土台が完了した状態です。
この状態でプレイしてみて、いくつか調整したい項目が出てきたので、以下の内容でブラッシュアップしたいです。

## 感じた課題
ゲームプレイを通じて感じた課題を書きます。

※ 今回は、ゲームプレイ本編部分に焦点を当てます。導入などは今回は対応しません。

----

ゲームプレイ中、AIとのやり取りで「今なにが起こっているか」が把握しづらいと感じています。
また、もともとベースとしていた「スキル」でのモックアップでは、AIに写真を送ったあとに、「現状どうなったか」についての状況説明画像を、画像生成AIを用いて作成し、それをフィードバックとして送っていました。

これを、本実装にも入れたいと思っています。
ただし、モックアップではチャットベースでのやり取りだったため、応答が遅くてもあまり違和感はなかったですが、本実装では音声でやり取りしているため、画像生成時間をそのまま待たせるとだいぶもたつくと思います。

そこで、音声でやり取りして会話をする、つまりストーリーは進めつつ、裏で画像生成を走らせ、生成完了したら「今こういう状況になった」と、後追いで説明する形としたいと思います。
なお、今回の全体の体験のイメージとしては、LINEやMessangerなどの、メッセージアプリを通じてやり取りしていることを想定しています。
音声通話とテキストチャットを同時に進行しているイメージですね。
なので、音声をメインチャンネルとしつつ、画像生成が完了したらメッセージチャンネルで送られてくる、ということを想定しています。

## ブラッシュアップ項目
前述したように、メッセンジャーアプリをイメージしたUIを想定しています。しかし、具体的なデザインはこれから行うため、いったん今回は仮デザインとして、メッセンジャーアプリを模倣したレイアウトでUIを構築してください。
メッセンジャーアプリの特色として、メッセージは相手が左側のバブル、自分が右側のバブルで色が違う、という感じです。
また、メッセージ欄の上端には、小さい横長の矩形エリアを配置し、音声通話中であることが分かるインジケータのようなものを配置してください。
iPhoneで、通話中に別アプリを前面に出すと、通話中であることを示すエリアが小さく残るあのイメージです。

加えて、メッセンジャーアプリ想定なので、写真撮影・送信については、メッセンジャーアプリのUIを踏襲してください。
つまり、チャット入力欄左側にカメラアイコンがあり、それを押すと写真撮影。撮影するとチャット入力欄上部に小さくサムネイルで写真を表示。その後、右側端に設置されている送信ボタンを押すことで送信、という具合です。

ただ、今回はテキスト送信はないので、テキスト入力欄は雰囲気だけで入力はできなくてOKです。
なお、AIからは画像と同時にテキストも送られてくる想定です。画像だけだと伝えきれない部分についてはテキストで補足する感じです。

## ハーネスのブラッシュアップ
今回、AIを介したゲームのため、いわゆるハーネス部分がとても重要になると思っています。
ハーネス次第で、このゲームが面白くもつまらなくもなると思っています。

体験フロー以外で私が気になっているのは、「AIが状況説明や、道具の使い方の認識を確認する」部分に、少しテンポの悪さを感じています。
もしかしたらここは、道具の使い方をわざわざAIが丁寧に確認するのではなく、写真送信時に伝えた「使い方」をAIがどう解釈するかもゲーム性にしたほうがいいかなと思っています。
言い換えれば、的確に指示を伝えられる人ほど、クリア確率が上がる、ということです。

こうした、「AIがどういう判断をするか」というのをしっかりゲームループとして構築し、開発中にチューニングできるようにすることが肝要だと思っています。

## 想定シナリオ
現在想定しているシナリオは以下の通りです。

1. ゲーム開始ボタンを押下する
2. ペライチでのゲーム説明を行う。（チュートリアルはAIが行うため、簡易的なもの。通話が必要、写真撮影が必要、などの最低限の前提知識のみ伝える）
3. ゲームを開始すると、メッセンジャーアプリ風UIが立ち上がる
4. ユーザは「なんだこれ？」と思う
5. そのさなかに、着信中、という表記とともに、応答ボタンが表示される
6. ボタンを押すとAIから発話「やっとつながった・・。私は・・」と自己紹介と、このゲームの主旨を、メタ的な視点はなしで、要するに体験者が本当に電話を受けて体験しているよう感じられるように状況を説明する
7. 体験者の写真撮影と名前、性別（男女・その他）を聞く（性別・名前は発話で）
    a. これは、「未来の自分」ということを前提にしているため、生成される画像などで利用したいため。
    b. 性別は、写真から判別できない可能性もあるため。
    c. 写真撮影と発話で伝えること自体がひとつのチュートリアルとなっている
8. 「私の具現化能力はもうあと残り少ない」という回数制限を伝える
9. 「よし、問題ないようだ」とともに、ここから本編が開始。
10. 現在の私の状況を説明する。としながら、今の状況を発話で説明。と同時に、裏で、今回のストーリーを前提とした今の状況の画像を生成AIに生成させる（例えば、手足が縛られているなら、それを伝える）
    a. これが、前述した「非同期で送られてくる画像」の仕様部分
11. いよいよここから本編スタート。脱出すべき、ということは前段で伝えているので、今どんな道具が必要かを伝え、写真撮影してもらう。制限時間があることも伝える。（私の能力も限界に近い。持ってあと◯分だろう、のように自然と伝える）
12. ユーザは写真を撮影してそれを送信。ここから先は今の実装と処理自体は基本同じ。ただし、前述したように体験を繰り返してチューニングするのがまさにここなので、チューニング可能なようにしたい。

※ 全体の仕様で伝えていませんでしたが、今回のアプリは日・英両対応が必須のため、UIにテキストを使う部分はこれを前提にしてください。
