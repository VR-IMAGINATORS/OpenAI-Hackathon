# 写真送信回数の制限

2026-09-15: 以下の回数制限・終了条件は [AI利用クレジット](../game-credits/spec.md) で置換。過去の合意記録として残す。

Status: user-requested (2026-09-14)

ユーザーは「行動回数ではなく送れる回数を制限、HELLは2回」を決定。difficulty-selectionとgame-core/story-integrationの行動上限・終了条件を本仕様で更新する。

- R1: Normal 300秒・4送信、Hard 240秒・3送信、HELL 180秒・2送信。難易度ボタンで直接開始。
- R2: 1回は非空の写真バッチ送信（最大2枚）。有効な画像をサーバーが受信した時点で消費。撮影・プレビュー・相談・行動・手持ち再利用は送信数を消費しない。追加・差し替え送信は新たに1回。
- R3: 同じrequestIdの通信再送は二重消費しない。不正画像・デコード失敗・受信前の失効は消費しない。受信後のAI認識失敗は送信済みとして数え、受信済み写真の認識を声で訂正できる。空バッチでの写真クリアは消費しない。
- R4: 0回では新しい写真送信のみ拒否。最後に受信した写真の利用、使用可能な手持ちの再利用、会話を許可し時計を継続する。消費済みは拒否、破損状態は判定へ引き継ぐ。
- R5: 勝敗は3障害突破、時間切れ、既存の中断条件で確定。送信0回や行動回数だけでは終了しない。API・画像生成・会話量の運用上限は維持し、回数制限撤廃を課金無制限として扱わない。
- R6: UIは残り送信回数を表示。0回では撮影・新規アップロードを無効化して「送信回数を使い切ったため手持ちで続行」を日英案内。通信結果不明の同じ要求の再確認は許可。
- R7: 新規開始・再接続・AIの公開状態・説明を送信制限で統一。既定シナリオJSONと設定検証も移行する。

対象外: GPT-Live方式の変更、物語や障害の削減、無制限の有料処理。実機・実API検証は別途。
