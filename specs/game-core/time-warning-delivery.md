# 時間通知の割り込み抑制（2026-09-15）

現行の動作は末尾の「developとの統合」を参照。先頭の調整と検証は2947c6b時点の記録。

## 原因と調整

試遊で、60秒未満の通知がユーザーの発言やAI自身の説明を遮ると報告された。従来のGameRuntime.tickは閾値検出と同時に、焦った口調を指定するinstructions.appendと、急かして次の指示を求めるcommentary.appendを送っていた。発話中かどうかの判定はなかった。

今回の方針は、時間が少ない事実をLiveへ渡し、会話の流れに合わせて後から添えること。

- 閾値検出時は`{ type: 'time_warning', message: ... }`をthinking.appendで一度だけ送る。通知用のinstructions.appendとcommentary.appendを除く。
- セッション開始時の指示に、ユーザーの発言・考え中の間、自分の説明・回答を最後まで優先すること、次の自然な切れ目で一度だけ添えることを定義する。切れ目がなければ保留し、終了結果が届いたら未発話分を取り消す。
- 日英の台詞と口調はconfig/game-core.jsonで編集可能。既定は「おっと、残り時間が少なくなってきた。」とし、急かす命令や質問を除いた。口調指定は時間通知に限定する。
- サーバー時計、停止中の抑止、閾値、再接続をまたぐ一度の発行、終了後の発行禁止は維持。チャット表示は閾値検出時のままで、音声は後になる場合がある。

## API仕様の確認

[Live API reference](https://developers.openai.com/api/reference/typescript/resources/live)では、thinking.appendは内部の推論・進捗情報用、commentary.appendはユーザーへ伝える情報用。字幕deltaは入力・出力とも発話の完了を定義せず、transcript-doneもない。appendの受領は発話・再生完了の保証ではない。

[Prompting GPT-Live](https://developers.openai.com/api/docs/guides/live-prompting)は、会話の進行・言い回しに裁量を与え、短い指示から実会話で調整する方針。全会話に一律の発話禁止を加えると相づちも抑えてしまうため、今回の待機指示は時間通知に限定した。

この仕様と報告に基づく実装上の判断として、字幕が一定秒数止まったことを安全な切れ目とはみなさない。既存のWebRTC音声を受けるLive自身へ切れ目の判断を任せる。新しいVAD、音声の強制停止、Realtime用イベントは追加しない。

## 検証と限界

自動テストは、入力/出力字幕の途中でも時間通知に即時発話・指示更新コマンドを発行しないこと、重複防止、停止・回復・終了、日英設定、長い台詞の欠落防止を確認する。プロンプトの生成も日英と無効設定を確認する。これらは音声で割り込みがなくなったことの検証ではない。

実Liveへの接続・録音による比較は未実施。thinking受領後に適切な切れ目で発話するか、繰り返さないか、終了時に保留を捨てるかはモデルの振る舞いであり、コードだけでは保証しない。再接続後の再発行はしないため、未発話の通知が失われる場合もある。

### 実機確認

サーバー再起動後の新規プレイで、残り60秒をまたいで以下を確認する。試遊を短縮するならthresholdSecondsをゲーム時間より少し小さく設定する。

1. ユーザーが長く話す・途中で考える・訂正する。通知が途中に割り込まず、まず発言へ応答する。
2. AIが長い説明をしている。説明を最後まで続け、その後の切れ目で短く添える。
3. 両者が話していない。自然に時間へ気づいた一言を発話する。
4. 判定待ち・接続回復待ちは通知せず、復帰後も結果の説明を優先する。
5. 通知後に急いだ口調や「次に何をする？」の反復が残らない。
6. 通知を保留している間にゲームが終了したら、終了結果の後に古い時間通知を付け足さない。
7. 再接続して同じ通知を繰り返さない。日本語・英語とPC・スマホで確認する。

## developとの統合

対象: 時間通知修正2947c6bと、developの3c1710c（ゲームループハーネス改善）。ユーザーの指示により現在のfeature/shibuya/game-polishへマージ。

### 両方の意図を残す動作

- developの音声活動推定・通知スケジューラーを採用する。通常60秒、最終15秒/待機上限3秒、期限・再接続・終了時の破棄を維持する。音声活動は実音量を分析して推定し、字幕の無更新から推定しない。
- 通常警告は両側quiet（ブラウザで800ms連続静寂）・再生可能・報告から2秒未満を確認後、今回のthinking.appendによる保留情報を送る。静寂は意味上の切れ目を保証しないので、最後の話しどころはLiveに任せる。
- 通常の台詞は「おっと、残り時間が少なくなってきた。」。説明・回答を最後まで優先する方針を残し、通常警告を行動結果の先頭へ結合しない。結果の後に独立した内部情報として渡す。
- 最終警告はdevelopの有限待機とcommentaryによる切替表現を維持。待機中の確定結果との一体化も最終警告に限り維持する。Liveには最終警告・終了結果を受けたら未発話の古い通常通知を取り消すよう指定する。
- warningsがv2設定の正本。timeWarningを参照し続けると新しい節目設定と有効/無効が食い違うため、セッション指示もwarnings.enabledに合わせた。日英の文面はwarnings.milestonesで編集する。
- 通常警告のthinking各断片にもnoticeKind/validUntilを付け、developのブラウザ配送前の期限・終了チェックとack処理を維持する。チャット表示は閾値検出時からoutbox発行時へ移る。通知受領と音声再生は引き続き別。
- developの写真起点の自律行動、結果確定前の中止・訂正、知識開示の制限、技術的失敗の回復処理を取り込む。

文字上の競合はhosted-runtime.tsとcore-runtime.test.ts。自動マージされたLive指示・新旧設定にも意味の食い違いがあったため、上記の方針で統合した。検証ヘルパーはdevelopの写真判断・応答差し替え引数と、今回の日英検証用の引数を両方残した。

実音声の割り込み抑制、静寂推定の精度、最終警告の自然さは未検証。上の実機手順では、通常警告の待機に加え、15秒到達時の古い通常警告の破棄、最終警告の3秒待機上限、最終警告後に通常警告を繰り返さないことを確認する。

統合後の検証: 全538テスト、型・JSON検査、Vite/サーバービルドが成功。実行条件は[ハーネス改善の検証記録](../improve-game-loop-harness/verification.md#時間通知修正とのマージ検証2026-09-15)を参照。
