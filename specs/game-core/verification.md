## 再開・実マイク確認

1. PCのリポジトリで `npm run probe:live` を実行する。サーバーは `.env.local` の運営設定を使用する。私有のルート `.env` は読まない。
2. ターミナルに表示されるフラグメント付きURLをPCのChromeで開く。127.0.0.1専用。トークンは同じタブのsessionStorageに保持するため再読込できる。サーバー再起動後や新しいタブで認証エラーになったら、ターミナルの最新URLから開き直す。
3. 検証会話を選択。ハサミを前提とする例ではハサミの写真を1枚選ぶ。「マイクで検証開始」を押し、マイクを許可する。
4. AIの「これをどう使う？」に続けて例文を声で話す。最初の簡易試験は「このハサミでロープを切れるかな？」→「じゃあ、そのハサミで切って」。相談でactionが増えず、後の指示で一度だけ増えるかを確認する。
5. 「結果JSONを保存」で記録を保存し、「接続を終了」。次の会話例へ進む。JSONは会話原文を含むためローカルの `artifacts/` で扱い、Gitに追加しない。
6. 24会話を確認し、誤消費・二重実行・未完文の実行・誤った訂正処理があれば記録する。発話の聞こえ方と待ち時間の体感も別途記録する。
7. サーバーはCtrl+Cで停止する。

画面だけを見る場合は `npm run probe:preview`。API設定を読み込まず、開始ボタンを無効化する。PowerShellのnpm引数転送に依存しないよう、実APIフラグは `probe:live` スクリプト自身に含める。

## 試験の範囲と上限

- 1接続あたり写真1枚・障害1個・最大120秒。起動後最大24 Live接続、96 Responses、1接続最大8 Responses。既存envの上限が小さい場合は小さい方を採用。
- 開始ボタンを押すまでは実API通信を開始しない。終了時はprobeを失効させ、上流Liveの終了を要求する。終了を確認できない場合は次の接続を許可しない。
- 入力イベントのHTTP受付は202。分類・行動判断を待たない。判定は既存AiServiceとResponsesの制限内で実行する。
- 原文断片、委譲、分類、予約、確定の時刻をJSONに保存する。ブラウザのrawEvents.receivedAtとハーネスのmeasurements.atを使い、委譲待ち・分類・行動判定を分けて集計する。プロバイダーのstart_ms/end_msは別の時計なので直接差し引かない。
- この画面は本編UI、スマホ撮影復帰、画像生成、AWS同時5人の検証を代替しない。localhost専用で、トンネル公開用の認証設計ではない。
