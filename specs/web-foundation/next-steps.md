# 土台の次に進める順番

ここは未実装の道順。個別仕様/計画は着手時にSpecWorkflowで具体化する。

1. **GPT-Liveの接続スパイク**: 審査員local→relay→Liveの接続、音声会話/切断、利用権限/対応ブラウザを確認。ゲーム判断はlocalに置く。費用/上限/保存/認証の運用条件を確定する。
2. **最小の1障害**: 写真の取得/対象認識、音声の使い方を短文表示、訂正、実行ボタン、構造化AI判定、状態確定を通す。行動消費と再試行を分離する。
3. **1プレイ**: JSONの3障害、4行動、持越品/破損/消費、全体時計とブロック待ち停止、成功/失敗を通す。既存試作の経験を参考にドッグフーディングする。
4. **緊迫イベントとメディア**: 条件評価/期限/続行可能な悪化、非同期画像、成否通知後の成功/失敗動画。無秩序なAI追加イベントや結果の逆転を防ぐ。
5. **審査向け仕上げ**: 固定シナリオの調整、PC/スマホ音声の通し、独立した審査員環境での起動、運営のHTTPS中継、提出物とOpenAI実利用説明、審査終了後の停止。

現時点の必須: GPT-Live音声、自由な提案への納得できる反応、最後まで遊べる体験、結果画像/動画。
動画は時間不足時の削除候補だが、黙って省略せずチームの判断を記録する。
この一覧は実APIの利用権限/モデル/予算/保存や各詳細が確定したという意味ではない。
