# エンディングタグの確認記録

2026-09-14 / `codex/ending-tags`。ローカル実装。共有作業ディレクトリに同時進行の動画MP4関連変更も存在するため、全体テスト件数は検証時の作業ツリーに対する件数。

## 実装

- 固定40タグ、日英表示名、AI用判定条件。
- 文章用の生成1回でタグと短文を返し、保存後に映像指示を別の1回で生成する。全確定行動を対象にし、タグの出典は映像用の直近2行動に限定しない。
- 文章を画像制作前に保存。storyStatusを公開し、動画未完成・無効でも文章を自動表示。
- 動画無効・素材なし・動画予算不足では文章のみ生成。Responses予算・1回制限を継承し、mockと中断は実生成なし。
- 文章のみの実行枠を動画枠から分離。画像・動画失敗でも保存済み文章を維持。

## 同日の失敗報告に対する修正

ユーザーから「動画生成に失敗しタグが表示されなかった」と報告された。実プレイのエラーコード・実行環境は未確認。コードでは、e7ab1ccのcreateEndingDesignが文章と映像脚本を一緒に生成・検証しており、映像側の失敗で文章を保存できない経路が残っていた。また動画有効プレイの文章生成は動画の実行枠待ちに含まれていた。

修正：全プレイを文章フェーズ→保存・配信→動画フェーズとする。story/directionは別のAPI応答・別の1回上限。動画の枠や映像応答の成功を文章公開の条件にしない。UIは保存済み文章を引き続き自動表示する。

- 最終 `npm.cmd test`: 362件成功、失敗0、skip0。
- `npm.cmd run build`: 型・JSON確認、UI・サーバービルド成功。
- 既定producerの回帰テストで、映像API失敗・不正な行動ID・不完全な映像応答の各ケースでもstoryStatus=ready、非nullタグ・本文が残ることを確認。
- 動画有効の次プレイが、前プレイの動画枠使用中でも文章を公開すること、動画待機中の期限切れでも文章が残ることを確認。
- 認証付きHTTPで文章公開後に映像準備へ進む順序を確認。
- Chrome headless 390×844で同じプレイの映像脚本エラー後にもタグと本文が表示され、再読込でも残ることを確認。API・メディアはfake。
- localhost:4310/healthzはversion=localで応答したが、起動中サーバーの再起動や公開環境への反映は実施していない。実プレイの障害解消・実AI品質は未検証。

初回確認の不足：文章を事前注入した画像失敗テストだけでは、文章と映像脚本を同じAI応答にした依存を検出できなかった。先行表示の確認は、保存より前の全工程と待機枠を含める。
