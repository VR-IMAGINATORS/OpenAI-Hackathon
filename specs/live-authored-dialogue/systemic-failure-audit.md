# 内部エラーをユーザーへ返す経路の点検

2026-09-16 / `255b643` に続く追加修正。依頼保持と再開だけでは不足しており、処理自体の失敗を減らす、というユーザーの指摘に基づく。

## コードで確認した問題と修正

| 問題                                                                                   | 対応                                                                                                             |
| -------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| 行動判定だけに修復があり、写真認識・写真の反応判断・意図分類の形式エラーはそのまま終了 | 共通の構造化応答処理で通信・解析・スキーマ不備を一度修復。副作用は完成した応答を検証した後に適用                 |
| 推論を含む出力が1,000トークン固定。途中切れでも同じ枠で再送                            | ゲーム内部専用の通常2,048・修復4,096枠。運営設定で縮小可能。汎用Responsesの上限は維持                            |
| 写真認識のIDが自由生成で、存在しない写真・在庫や二重の出所を許す出力スキーマ           | 実在IDの選択肢と片方だけの出所をスキーマで指定。違反時は状態反映前に修復                                         |
| 写真判断・意図分類の応答読み取りで途中切れ・拒否の区別がない                           | 完了状態を共通に検査。不完全なJSONを確定しない。拒否やcontent_filterを修復対象にしない                           |
| 本来の上流400/401などが502にまとめられ、通信の一時障害と同様に再送される               | 内部エラーに元のHTTPステータスを保持し、再送可否で使用。上流本文は記録しない                                     |
| タイムアウトは呼出し元の待機だけを止め、通信の中止を要求しない                         | transportに中止信号を渡す。実通信が終了するまでは同時実行枠を保持するため、遅い通信との二重実行も防止            |
| 同時実行枠が一瞬満杯でも回数上限と同じエラー                                           | ゲーム内部の通常要求のみ最大5秒・20件まで待機。待機はAPI試行回数に加算しない。回数上限・終了・中止は引き続き優先 |
| 指示分類のエラー通知後も委譲が待機状態に戻り、期限切れで同じ失敗を再通知               | 内部修復後の最終エラーでは当該委譲を終了。発言の根拠を残し、同じ期限切れ通知を追加しない                         |
| ハーネスが24,000文字まで受け入れる一方、送信側の入力上限は16,000文字                   | 送信前の上限チェックを実際の契約に一致させる。長すぎる入力を繰り返しAPIへ送らない                                |

`max_output_tokens` は推論と最終出力の合計を制限する。枠を使い切ると、表示用文章をまだ出していなくても `incomplete` になる。[OpenAIの公式仕様](https://developers.openai.com/api/docs/guides/reasoning#allocating-space-for-reasoning)。従来枠が実試遊の失敗原因だったと断定できるログはなく、2,048/4,096が十分かどうかも実APIでの測定が必要。

## 回復範囲と検証

`npm run check`、`npm test`（932件すべて成功）、`npm run build`、`git diff --check` 成功。実API接続・課金は行っていない。

模擬上流で写真認識・写真判断・意図分類・行動判定の各段階の最初の応答を壊し、同じ写真と指示から最後まで進み、エラー通知ゼロ・行動一回・結果通知一回・クレジット一回になることを統合テストする。途中切れは出力枠を増やして修復する。永久失敗の2回上限、拒否の非再送、失効・中止、回数上限、タイムアウト後の実通信枠、待機中の中止、汎用APIへの大きな枠の流用拒否も自動検証する。

確定前のGameSession検証を維持する。通常の「道具を試したが失敗」は再試行しない。安全な結果が得られない場合に、エラーを隠して成功や物理的失敗を捏造しない。

## 限界

- 実API・実音声・スマートフォンでの発生率比較は未実施。実際のエラーが何割減るかは未測定。
- 出力枠と形式修復の対象拡大により、実APIの出力トークン利用量と待ち時間が増える場合がある。既存のプレイ・全体のAPI試行回数上限は維持。
- 永続的な認証・設定不備、実際の回数上限、長引く混雑、モデルの拒否、長すぎる必須入力は成功扱いにしない。
- 型検証後の全ての意味的な矛盾を自動修復する実装ではない。写真・指示分類後の参照や権限、知識変更は各既存の検証で引き続き拒否する。ゲーム行動の状態矛盾はGameSessionの修復対象。
- 日本語の誤読そのものは今回の修正対象ではない。
