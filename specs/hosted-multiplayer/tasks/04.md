### Linux実プロセスSIGTERM検証（2026-09-13）
- build済み`call-to-the-past:hosted-smoke`をmock/ダミー設定で起動し、実際の`apps/server/index.js`（コンテナPID1）へ`docker stop --time 120`でSIGTERMを送信。health確認後に`drain_started`→`drain_finished(count=0)`が出力され、exit code 0で正常終了した。
- 別コンテナのNode probeからbuild済みcreateHostedAppへfake transportを注入し、AiServiceでLiveを1件作成。SIGTERMハンドラはindexと同じserver.close→runtime.dispose→server.closeAllConnectionsを使用。`fake_live_ready(count=1)`→`drain_started`→`fake_hangup_confirmed(count=1)`→`drain_finished(count=0)`→`probe_shutdown_complete(hangups=1,liveBusy=0,pendingCreates=0)`を確認しexit code 0。
- 後者はapp/AiServiceの実プロセス終了検証であり、indexへのtransport注入や実OpenAI WebRTCの停止検証ではない。実API接続・AWS SIGTERM猶予・強制kill時の上流停止保証は未確認。
- 2つの検証コンテナは停止・削除済み。probeは無秘密の`artifacts/hosted-sigterm-probe.mjs`（Git対象外）。Docker29.7.2では`--time`が非推奨の案内が出るため、以降の手順は同義の`--timeout 120`も利用可能。
