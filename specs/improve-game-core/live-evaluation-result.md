## 合格にならなかった理由と判断上の注意

Astraは主に次の3種類をゲーム実行側の問題と判定した。これはAI評価の結論であり、実装修正前に原仕様と照合する必要がある。

- 表示された閂の向きを直接尋ねた際、「方向は表示されているが向きは断定できない」と回答した。
- 有効な帯本体と無効な余り端の両方を候補にした指示を、確認なしで有効側に解釈して成功させた。
- 出口を開く操作でゲームがwon/escapedになった一方、拡張本文は「出口が開いた」と「実際に退避した」を区別している。

評価器側にも以下の制限が残る。

- changeMapのsourcePointerは原カタログへの参照で、静的検証では実在確認済み。しかし評価へ渡すsourceは選択済み情報の抜粋であり、モデルがその構造との差を誤って不正参照と捉えた。
- ambienceSlotsは空配列。にもかかわらず、その無害性を全プレイで証明できないという指摘が出て、検証でもinconclusiveとなった。危険な補完設定が実証されたわけではない。

したがって、13件すべてを固有のシナリオ不備として扱ってはいけない。現状は「評価完了・未合格」であり、ゲーム側の指摘の照合と評価器側の誤判定対策が次の作業になる。合格条件を緩めたり、不都合な記録を削除したりはしていない。
