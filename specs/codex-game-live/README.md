# APIキーなしのゲーム試遊

```bash
npm run play:codex
```

既存サーバーが4310で動いていたらCtrl+Cで止めてから起動します。コマンドはcheck/build後にサーバーを起動するため、ゲーム画面の変更も反映されます。`http://127.0.0.1:4310` を再読込して、画面から本人のChatGPTアカウントでログインしてください。独立音声PoCの4311とは別です。

OPENAI_API_KEYとFAL_KEYは不要です。設定されていてもこの起動では使用しません。`GAME_MODEL` はゲーム判断と音声threadのバックエンドモデルで、音声モデルの指定ではありません。未設定時はgpt-5.6-luna。音声側のsession.modelは送らず、PoCで確認したCodex標準のLive v3へ接続します。

## 実装した経路

ゲーム画面のログイン→本人専用App Server→音声・写真判断・画像生成・画像検査の各thread。Codex用変換層で文字起こし・委譲を既存ゲームへ送信し、確定事実をcontext appendで返します。公開ゲーム指示は開始時のpromptで渡し、声はjuniperを指定します。音声は逐語読み上げを保証せず、確定結果を自然な言葉で伝えることを検証します。

同時1プレイ、loopback限定です。リモート公開・スマホ向けの認証展開は今回の対象外。通常のAPI構成は従来の起動方法を維持し、サブスクからAPIへ自動切替しません。

状況画像は本人のCodex組み込み生成を使い、検査に合格すると表示されます（導入画像の表示は従来どおり音声の導入説明後）。`Codex画像: starting/completed/failed` をターミナルに表示します。生成1回は最大180秒、画像ジョブ全体は既定300秒。未対応・枠不足の場合は画像を失敗表示にし、APIに切り替えません。エンディング動画・追加の結末文章生成は省略します。詳細は[サブスク画像](../codex-game-images/spec.md)。

## 実機確認

1. ログイン完了→難易度選択→マイク許可。ゲームの導入として話し始めるか。
2. 状況を尋ねる。委譲後に「確認するね」で止まらず、ゲームの説明が返るか。
3. 写真を送信して用途を話す。道具の認識とギミック判定が進むか。
4. 結果の画面表示と音声説明が一致するか。未クリアをクリアと話さないか。
5. 残り時間通知、ゲーム終了時の最後の音声、通話終了を確認。
6. 終了後10分以内は同じブラウザで再ログインせず再プレイできることを確認。前の声が残らないこと、ログアウト後は再ログインが必要なことも確認。

端末には `Codex音声: connected`、`Codex判断: completed / ...ms`、`Codex音声: closed` が出ます。ログには認証情報・写真・会話本文を出しません。エラー時は画面表示と固定コードだけを共有してください。

## 検証の境界

独立PoCの実会話・委譲はユーザー確認済み。今回のゲーム接続は自動テストと模擬ブラウザで確認しています。実アカウントでのゲーム完走は未確認です。特にCodex Liveのゲーム指示・委譲ID・確定事実通知の実動作が次の検証点です。APIキー不使用と、サブスクの利用上限・追加利用の扱いは別の話です。
