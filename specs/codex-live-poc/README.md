# GPT-Liveサブスク接続の実機テスト

調査上は、固定版App Serverに音声接続用の実験的RPCがあり、検証を進める根拠があります。ただし **サブスクでのGPT-Live接続成功はまだ確認していません**。これは独立PoCで、ゲーム本編の音声切替ではありません。

## 実行

```bash
npm run poc:codex:live
```

`http://127.0.0.1:4311` をPCのブラウザで開きます。既存ゲームの4310番とは別です。ビルドや `.env.local`、APIキーは不要です。既存PoCと同じ対応Codex実行ファイルが必要です。

1. 「ChatGPTでログイン」→OpenAIのページにコードを入力して、本人のアカウントで承認。
2. 元の画面に戻り「マイクを接続」を押して、マイクを許可。
3. 「こんにちは、聞こえますか」と話しかけて返答を確認。
4. 「テスト文を送信」を押し、サーバーから送った文章への音声の反応を確認。押す前後はマイクへ話さず、ボタン送信との関係を確認する。送信文は「こんにちは。音声接続のテストです。こちらの声が聞こえますか。」。文章どおりの読み上げは合格条件にしない。
5. 「停止・ログアウト」を押し、音声終了通知と専用プロセス破棄の表示を確認。

音声は要求開始から60秒で停止処理を開始します。終了通知の確認には最大約5秒、続いてプロセス停止/一時領域削除に数秒かかる場合があります。status通信が20秒途絶えたときも停止します。サーバー終了はCtrl+Cです。

録音や会話内容の保存はありません。画面は受信イベント名、モデル名、受信音声byte数を表示します。音声byte数は通信の証拠であり、人が聞き取れる音声の証明ではありません。再読込後の音声再接続は未実装なので、停止・再ログインしてください。

## 固定条件

- 音声開始時の独自 `prompt` は指定しません。サブスク経路の標準設定で接続を検証します。ゲーム向けのキャラクター指定が可能かは未確認です。

- 音声のモデルは **指定なし（Codex標準）**、プロトコルは **v3**。実機で `session.model` の指定が拒否されたため、フィールド自体を送信しません。GPT-Liveかどうかは報告モデルで確認し、未報告なら未確認、別モデルなら停止します。モデルを替えて自動再試行するfallbackはありません。
- `GAME_MODEL` はこのPoCでは使いません。App Serverのスレッド側はgpt-5.6-lunaを指定します。音声側がバックエンド処理を起動する可能性はあり、純粋な音声枠だけの消費とは未確認です。
- `clientManagedHandoffs` を指定しますが、これだけでゲーム向けの委譲制御が同等になるとは扱いません。今回は任意ツールを公開せず、固定テキスト送信への音声反応までを試します。委譲結果を音声へ返す処理は未実装です。
- ログイン・音声は専用プロセスとCookieで分離。APIキーを子プロセスへ渡さず、公開APIへの代替呼出もありません。
- モデルが相手から報告されなければ「未報告」です。明示的に別モデルが報告された場合はクライアント側でも停止します。
- `listVoices`はv1/v2の一覧を返すため、v3対応やgpt-live-1利用権の確認にはなりません。

## 共有してほしい結果

```text
ログイン: 成功 / 失敗
マイク接続: 成功 / エラーコード
相手から報告されたモデル: ... / 未報告
話しかけた際の返答: 聞こえた / 聞こえない
テスト文送信への反応: あり / なし（読み上げ / 内容への返答 / その他）
受信イベント種別: ...
音声終了通知: 確認済み / 未確認
専用プロセス破棄: 確認済み / 未確認
```

認証コードや会話の本文は共有不要です。`RPC_ERROR_...` や `VOICE_UPSTREAM_ERROR` の場合、そのコードを共有してください。認証済みでも、モデルの利用権・rollout・実験版の接続仕様で失敗する可能性があります。停止通知が未確認の場合は、繰り返し接続せず先に原因を確認します。

診断だけなら `npm run poc:codex:live -- --check`。未認証の音声一覧取得を試すだけで、接続成功を意味しません。

### 接続エラーの診断

サーバーをCtrl+Cで終了し、npm run poc:codex:liveで再起動、ブラウザを再読込して接続します。最新版のエラーには「診断版: startup-detail-v2」が表示されます。この文字がなければ旧プロセスまたは旧画面です。

接続開始時のエラーは、既知語の許可リスト方式を廃止し、本文の技術的な説明を残します。APIキー・Bearer/JWT・認証フィールド・URL・メール・ローカルパスなどの既知形式を伏せ、最大1600文字を本人のローカル画面に表示します。ファイルやコンソールへ本文は保存しません。接続後のエラーは分類のみです。共有前に予期しない個人情報が残っていないか確認してください。

prompt除去後も拒否が続いており、接続の原因は未確定です。診断版と詳細を含むエラー行を共有してください。分類は原因確定を意味しません。過去のエラー原文は保存していないため再接続が必要です。
