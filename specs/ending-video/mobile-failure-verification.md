# モバイル試遊のエンディング失敗への対応

2026-09-14。作業ブランチはユーザー指定の `feature/shibuya/integrate-mock-features`。

## 調査で確認したこと

- 報告は未デプロイの `npm.cmd run play:mobile` で発生した。従来の表示・ログでは制作段階と原因を区別していなかったため、報告されたプレイの失敗原因自体は確定できない。
- ローカル設定は動画生成が有効で、falキーも設定済みだった。秘密値は表示・記録していない。動画回数上限は1回だったため、合意済みの100回へ `.env.local` の該当値だけを変更した。この私有設定はコミットに含めない。
- GitHubのSecret・Variablesはローカル試遊へ自動反映されない。起動時に有効状態・実際の回数上限・ローカル設定を使うことを表示するようにした。

## 修正

- 直近2行動のうち最後の1行動だけを映像化するとき、以前は先の行動に対応する画像で連続性を検査していた。このため正しい参照画像があっても制作に失敗し得た。利用可能な行動前画像の一覧を脚本生成へ渡し、採用した最初の行動のバージョンに一致する画像を編集に使う。各API要求の添付画像は最大2枚を維持する。
- 物語、画像生成、画像検査、fal送信、取得、保存の失敗を固定コードで区別する。上流サービスの応答本文・キー・画像・会話は公開表示にも診断ログにも含めない。
- プレイヤーには失敗の説明を表示し、「不具合報告用の情報」でコードを確認できるようにした。既存プレイの再送や自動再試行は追加しない。

2. 起動表示でエンディング動画が有効、全プレイヤー合計100回であることを確認する。

4. 再び失敗した場合は「不具合報告用の情報」のコードを確認する。これにより次の調査対象を特定する。

## 再試遊後の変更：終了時の完成画像で制作する

同日の再試遊で「動画の元になる最後の場面画像を用意できませんでした」と報告された。旧処理は最終messageIdの画像だけを待ち、失敗・キャンセル時には以前の完成画像があっても停止していた。ユーザー指示に従い、終了時点で完成している画像を素材として固定する方式へ変更した。

- ゲーム内の時点が最新の完成画像を選び、直近行動の行動前画像も同時に固定する。最終画像の未完成・失敗・キャンセルで待ち続けない。文字起こし猶予やジョブの待機中に完成した画像は追加しない。
- 古い画像の時点と、描くべき確定状態を脚本・画像編集・検査へ明示する。最新の行動結果や解除数を画像に合わせて巻き戻さない。
- 完成済みの場面画像が1枚もない場合は素材不足として表示し、falへ送信しない。

課金なしの制作処理テストでは、最終画像完成済み／未完成／失敗／キャンセル、初期画像のみ、終了後の画像完成、完成画像なしを確認した。以前の1行動選択の回帰確認も維持している。画像が完成した順序とゲーム内の順序が逆の場合や、他プレイ・未検査・写真素材を除外することも確認した。

追加修正後の `npm.cmd test` は344件成功、失敗・skipなし。`npm.cmd run build`（型・設定検証を含む）、変更コード7ファイルのPrettier検査、`git diff --check` も成功。AI・fal・動画データは模擬であり、実生成・実機再生の成功は未確認。設定の追加は不要で、上記手順のとおりサーバーを再起動して新しいプレイで確認する。
