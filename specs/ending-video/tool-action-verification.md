# 道具と解除方法の画像・動画への引き継ぎ

2026-09-15、`feature/shibuya/game-polish`。ユーザーが合意した「途中画像に道具・作用・結果を残し、リザルト動画でその行動を優先する」修正。

## 変更

- 画像のgameVersionに対応する確定行動を複製し、HTTPアプリ内の受け渡しから画像ジョブへ引き継ぐ。次のギミックへ進んだ場合も、直前に使った道具・用途・対象・前後の状態を失わない。
- 途中画像は、使用道具・作用箇所・確定した結果が同時に分かる行動直後の構図を優先する。生成と検査に同じ行動情報と道具状態を渡す。未公開ギミックのfactsや非公開の機構説明を追加しない。
- 動画は既存の直近最大2行動と参照画像の条件を維持し、行動前画像がある道具による成功を優先候補として渡す。演出指示で道具の識別・接触・動き・解除結果を明示し、読み取りやすい1行動にも絞れるようにする。
- 動画用の開始・終了画像にも選択した道具・用途・成否・道具状態を直接渡す。開始は行動前、終了は確定した結末を優先し、消費した道具の復元や脱出の巻き戻しを要求しない。

## 実生成・試遊

実APIでの画像・動画生成、GPT-Live音声、スマホ撮影は未検証。自動テストは確定データの受け渡しと制約を検証しており、生成物に道具が実際に描かれることを保証するものではない。道具の見えやすさだけを理由に再生成回数を増やさず、既存の呼出し回数・期限を維持する。

新規プレイで、ハサミによる切断や硬貨によるネジ操作などの具体的な成功を試し、途中画像に「道具・接触箇所または作用の跡・解除結果」が見えるか、動画で同じ道具と使い方が分かるかを確認する。失敗・部分進展・消費した道具についても、未確定の成功や道具の復元が描かれないかを別に確認する。画像不足時は既存の余韻演出に制限される。
