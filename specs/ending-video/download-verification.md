# リザルト動画のダウンロード

2026-09-15、`feature/shibuya/game-polish`。

## 実装

- 動画完成後に「動画をダウンロード / Download video」を表示する。再生エラー時も利用でき、生成待ち・生成失敗・認証失効・保持期限切れでは表示しない。
- 既存の所有者認証付き動画GETに `download=1` を追加し、`Content-Disposition: attachment` と `call-to-the-past-{playId}.mp4` を返す。通常再生の応答は従来どおり。保存のための再生成・保持期限延長は行わない。
- ブラウザのダウンロード機能を使い、JavaScript側で動画全体をBlobへ複製しない。サーバーの所有者認証・保持期限・Range・HEADを共通で適用する。

## 検証

作業中に音声終了処理の別変更が入り、共有作業ツリーの既存HTTPテスト2件で12秒後のRuntime破棄／再プレイの期待が不一致になった。その差分には変更を加えず、`9b51776` に本件の差分だけを適用したコピーで以下を確認した。

| 項目 | 結果 |
| --- | --- |
| 全自動テスト | 763件成功、失敗・skipなし |
| `npm run build` | 型・標準JSON・18構成、UI・サーバービルドに成功 |
| ダウンロードHTTP | MP4本文一致、固定ファイル名、GET・HEAD・Range、本人限定、未完成409、失効410、不正パラメータ400、保存による追加生成なし |

`apps/web/tests/ending-smoke.cjs` は共有作業ツリー上の変更済みUIで実行し、Chrome headlessのスマホ幅390px／320pxで成功。日英表示、実際のダウンロードイベント・ファイル名・保存バイト列一致、保存後もリザルトを維持、再生エラー時の保存導線、折りたたみ・認証失効・保持期限切れを確認した。ネイティブのダウンロードはPlaywrightの通信モックを通らないため、試験用HTTPサーバーで固定バイト列を配信している。

API・動画は模擬データ。実AI動画の生成、iPhone／Android実機での保存先・再生は未検証。端末の写真ライブラリへの直接保存は提供しておらず、ブラウザの保存操作を使う。
