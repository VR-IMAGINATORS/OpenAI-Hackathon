# 初期画像だけのエンディング制作

2026-09-14、`ENDING_START_INSPECTION_REJECTED` と、一度も行動に成功せず行動画像がなかったプレイが報告された。以前の不合格画像と検査理由は保存されておらず、そのプレイの具体的な不合格理由は特定できていない。コード上、初期画像だけでも行動前の参照として採用でき、行動の再現を選ぶ余地があった。

ユーザー合意に基づき、行動後の完成画像がない場合は、提示済みの伏線と確定した終了状態を使った余韻の演出に限定する。成功回数を条件にせず、失敗・部分進行・道具の損傷を保持する。行動していない場合は新しい試行を創作しない。完成画像が1枚もない場合は既存の文章だけの経路を使う。

## 変更

- 演出AIへの構造化出力を `mode=aftermath`、`usedActionIds=[]` に限定し、サーバーでも検証する。文章と演出には全確定行動と提示済み根拠を引き続き渡す。
- 余韻の開始・終了画像では共に確定した終了状態を使う。生成と検査に同じ目標facts、道具の状態、結末種別、演出段階を渡し、初期画像との見た目の差だけで確定した進行を取り消さない。
- 余韻には新しい行動や成功の見せ場を要求しない。拘束の消失や未確定の脱出などの重大な矛盾の検査は維持する。
- 明示的な検査不合格後の1回の修正では、不合格の画像そのものと連続性の参照画像を渡す。再検査の比較元は元の参照（終了画像なら合格済み開始画像）を使い、不合格画像を正本にしない。添付画像は最大2枚、各画像は最大2回、fal送信は最大1回のまま。

## 検証

`tests/ending-aftermath.test.ts` では実際の `EndingJobs`、`AiService`、画像処理、結果保持を使い、以下を課金なしで確認する。

- 0行動／失敗のみ／成功ありで初期画像しかない場合の余韻への限定。
- 成功0回でも行動後の完成画像がある場合の行動演出。
- 完成画像がない場合の文章保持と画像・fal要求0回。
- 生成・検査の目標状態と道具状態の一致、確定した失敗と伏線の保持。
- 不合格画像を渡す1回の修正、再度不合格なら停止してfalへ送信しないこと。
- AIが限定された出力契約に反して行動演出を返した場合のサーバー拒否。

AI応答・画像・fal・動画データは模擬である。実AIの画像検査の合格、実fal動画の生成、実スマートフォンでの再生成功を示すものではない。

`npm.cmd test` の再実行は全370件成功、失敗・skipなし。`npm.cmd run build`（型・設定検証を含む）、変更コードのPrettier検査、`git diff --check` も成功した。全体テストの初回は既存の `core-scene-http.test.ts` の画像取得で404の期待に対して400となる1件の失敗があったが、当該ファイルの個別実行（5件）と全体の再実行では再現しなかった。当該テスト・画像取得処理への変更は行っていない。

設定の追加は不要。起動中の試遊サーバーを終了し、`npm.cmd run play:mobile` でビルドし直して、新しいプレイで確認する。
