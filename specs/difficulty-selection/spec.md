# 難易度選択とコンパクトな開始画面

Status: user-requested (2026-09-14)

## 要件
- R1: 上部の装飾・見出し・説明・余白を縮小し、スマホの表示領域（390×664、375×600 CSS px）で難易度と開始ボタンまでスクロールなしで表示する。拡大文字や極小画面ではスクロールを許す。
- R2: 合言葉入力と3種類の難易度別開始ボタンを同じ画面に配置。各ボタンに難易度名・時間・回数を表示し、押すだけでその難易度の導入へ進む。ボタン内のStart／開始の文字は表示しない。ノーマルは緑、ハードはオレンジ、ヘルは赤で区別する。上部の矢印は画面内に収まる範囲で拡大。選択用radioや別の共通開始ボタンは置かない（2026-09-14ユーザー補足）。英語名は Normal / Hard / HELL、日本語はノーマル / ハード / ヘル。最高難易度名はユーザーがHELLに決定。
- R3: Normal は5分・4回送信、Hard は4分・3回送信、HELL は3分・2回送信。2026-09-14の最終合意で行動上限から写真送信上限へ変更。0回でも手持ちの道具で行動できる。詳細は [写真送信回数の制限](../photo-send-limit/spec.md)。3障害と既存の成功判定を維持する。
- R4: 未認証で空欄または空白だけのまま開始すると、言語に応じた合言葉入力のポップアップを出し、入力欄にフォーカスする。認証失敗は開始せず案内。
- R5: 認証成功後は追加の開始クリックなしで既存の導入へ進む。マイク準備・プレイ枠作成は既存の着信応答時。導入後にゲーム時計開始。
- R6: サーバーが難易度に対応する上限を固定し、再読込・再送で変更されない。未指定の旧API呼出しは既存シナリオ設定を維持。不正値や任意の上限指定を拒否。
- R7: 現在のブランチで実装・検証してコミットする。実API・実機未検証を成功と報告しない。

## 境界
公開構成は ../hosted-multiplayer/spec.md、ゲーム基盤は ../mobile-playtest/spec.md を継承。本仕様は開始UIと選択時の上限のみ更新する。GPT-Live、障害数、判定、エンディングは変更しない。
