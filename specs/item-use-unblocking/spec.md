# 写真と音声指示によるアイテム使用の停止撤廃

作成日: 2026-09-16。今回のユーザー要求と追加回答に基づく変更仕様。

## 方針

写真送信後に用途を音声で伝えたとき、通常の発話・言い直し・断片的な文字起こしを理由にアイテム使用を中止しない。ユーザーが選択した例外は「明示的な『待って・やめて』だけ残す」。道具の破損・喪失など、ゲーム内の危険に対する実行前の承認待ちも撤廃する。

追加のユーザー方針: 停止表現の取りこぼしで行動が進むことはある程度許容する。停止の網羅性より通常の使用指示が進むことを優先し、曖昧な発話まで停止扱いする仕組みは再導入しない。

用途が自明な写真だけでも一度使用する既存の動作は維持する。具体的な使用は通常の成否判定へ渡し、実行前の写真拒否を保持して繰り返し使用を差し止める処理は撤廃する。成否・物理的な成立性・ゲーム状態の検証を自動成功へ置き換える変更ではない。

本書は [ゲームループハーネス仕様](../improve-game-loop-harness/spec.md) の H02/H05/H06/H07/H10/H11、A02/A05/A07/A10、および関連計画・データモデルのうち、危険への確認待ちと判定途中の自動中止に関する部分を更新する。

## 調査した経路と扱い

| 箇所 | 従来の処理 | 今回の扱い |
| --- | --- | --- |
| `apps/local-server/hosted-runtime.ts` | 判定中の全ユーザー字幕を停止用AIへ送り、不明・変更・失敗・5秒経過でも中止 | 自動中止を撤廃。明確な停止依頼だけ中止し、通常の指示では停止通知を出さない |
| `apps/local-server/game.ts` | 字幕ごとの保留、5秒タイマー、判定開始前・結果確定前の保留待ち | 保留機構を撤廃。明示停止と技術的な失効に使うキャンセルは維持 |
| `apps/local-server/harness-decisions.ts` | 停止用AI分類、写真の拒否・危険確認 | 停止用分類と事前拒否・危険確認の選択肢を撤廃 |
| `apps/local-server/game-harness.ts` | 写真拒否の保持と再審査、危険提案の保持・同意待ち | 撤廃。使用要求は通常の判定へ進める |
| `apps/local-server/core-intent-ai.ts`、`packages/shared/conversation.ts` | 危険確認を会話へ戻すモデル契約と状態 | 危険提案の契約・副作用を撤廃 |
| `apps/local-server/live.ts`、`creative-acceptance.ts`、`config/game-core.json` | 危険への同意待ち、判定中の訂正による停止を促す指示 | 明示停止だけを尊重する指示に統一。中止が確定していないのに「止めた」と告げない |
| `packages/server/ai-service.ts` | 停止判定AI用の専用API・同時実行枠 | 撤廃。通常のAPI予算・同時実行制限は維持 |
| `apps/local-server/intent-coordinator.ts` | 写真処理中の音声を `wait` として評価し、試行回数や受付期限を消費 | 処理できるまで実際の指示を保持。待機中に分類試行数と受付期限を消費しない |
| `apps/local-server/conversation.ts` | 停止後の訂正字幕を実行根拠に昇格 | 使われなくなった昇格処理を撤廃。重複・旧世代・同じ行動の再実行を防ぐ根拠管理は維持 |
| `apps/web/src/PlayScreen.tsx`、`apps/server/app.ts` の音声活動通知 | 発話中/無音の通知 | 行動中止には使用されていない。時間警告・導入・最終発話に使う処理を維持 |
| 同UI/HTTPと `game.ts` の入力・状態検証 | 接続、所有権、写真上限、残高、同時処理、旧状態の検証 | 誤課金・他プレイへの干渉・二重確定・終了後の実行を防ぐため維持 |

## 受け入れ条件

1. 写真だけの自動使用が一度確定する。
2. 自動使用の判定中に「ハサミで切って」「じゃあハサミで」「いや、ドライバーで外そう」などを受けても、中止せず一度確定する。分割文字起こしも同様。
3. 停止判定AIを呼ばず、旧5秒制限を超えた判定も通常どおり完了できる。
4. 明示的な「待って・やめて」は、未確定の行動にだけ適用する。否定・物の固定を指示する表現などを停止と誤解しない。確定済みの結果は巻き戻さない。
5. 道具を失う可能性だけで同意待ちにせず、具体的な使用を通常の成否判定へ渡す。
6. 写真処理中に音声が複数断片で届いても、処理待ちだけで分類試行上限や受付期限に達しない。写真処理後は最新の根拠で一度処理する。
7. 二重実行、不正参照、操作権変更、終了・期限、AIの不正出力への保護を維持する。

## 検証と反映の範囲

自動テスト・型検査・ビルドの結果は [検証記録](verification.md) に記録する。模擬AIでの競合再現と、実GPT-Liveでの発話精度・自然さは別の検証とする。

この依頼ではローカルのコード修正・検証を実施する。本番への反映はリリースの指示がある場合に行う。実装・検証時のブランチは `fix-block`、ユーザーのコミット依頼時のブランチは `fix-block-function`。既存の未追跡企画・動画資料は変更しない。
