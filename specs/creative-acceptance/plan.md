# 実装計画

承認根拠は会話の推奨案と実装指示。実装上の詳細はその範囲で具体化した。AGENTS.mdに従いマルチレビューは実施しない。現在のブランチを維持する。外部issueを追加せず、作業記録はこのディレクトリに保存する。

## 1. 判定と記憶（R1/R2/R5/R6/R8）

- 新規 `apps/local-server/creative-acceptance.ts`: 構造化した分類、作用の列挙、プレイ内台帳。サーバーの乱数で1/3を選ぶ。固定した乱数をテストで注入可能にする。
- 変更 `packages/shared/core-config.ts`, `config/game-core.json`: `creativity.enabled` と `creativity.successProbability`。省略時は従来動作、標準設定は有効・1/3。
- 変更 `apps/local-server/game-ai.ts`: 有効時、既存の1回の判定応答に分類・短い正規化した方法・既存案との同一性・公開可能な作用enumを要求する。無茶案は成立を仮定した結果候補を作る。抽選結果をモデルに渡さない。
- 変更 `apps/local-server/game.ts`: 予約時に同じ障害状態の既存案を凍結して入力へ渡す。候補の状態遷移/在庫/完了条件を検証し、中止確認後に台帳で結果を選択、既存の一度だけの確定経路に載せる。当たりの無茶案は現在障害の完全達成を必須にする。
- 台帳は写真ID/在庫ID/行動IDではなく、障害の実状態・道具名と状態・用途の正規化を使う。意味の同一性はAIの既存案ID照合で補い、参照先をコードで検証する。再送や同じ案の通常案への分類変更でも前の抽選を維持する。上限時に古い案を追い出して再抽選可能にはしない。

## 2. 入口と説明（R3/R4/R7）

- 変更 `harness-decisions.ts`, `core-intent-ai.ts`, `hosted-runtime.ts`, `live.ts`: 共通方針を使い、物性の無茶だけなら既存の実行経路へ送る。対象外の物体・保留・リスク・写真認識訂正の境界は維持する。
- 非公開の判定説明を公開しない現行の `projectPublicJudgment` を維持する。無茶案の成功だけ、検証済みの作用enumと使用道具名から日英の短文を作り、確定結果・画像・エンディング履歴へ引き継ぐ。
- シナリオの機構と完了状態は維持。通常物性の文言より今回の限定された判定方針を優先することをpromptで明示する。

## 3. 検証・コミット

台帳の境界値、同一案/意味の照合/別案、0/1/1/3設定、通常案/対象外、リトライ/中止、全段階のprompt、公開説明の秘密非流出をテストする。既存の模擬providerも必須の新応答形式へ対応する。対象テスト→`npm run check`→`npm test`→`npm run build`。仕様/実装/検証の意味のある区切りでコミットし、pushはしない。

公開HTTP API変更はないためcontractsは追加しない。既存認証・所有権・料金・ログ方針は維持。カバレッジは各節のR番号で全要件を確認済み。実AI評価の未実施を検証記録に残す。
