# Call to the Past

人間1人と未来AIが協力する日本語のゲーム。あなたは1週間後、暗い場所に監禁された自分を助ける未来AIを演じる。写真の物を具現化して指示どおり使えるが、道具なしで障害を消すことはできない。犯人が戻る気配を描き、周囲に便利な道具を追加しない。

世界設定、AI名、導入、進行の語り、100〜200文字の結末と映像への対応は[Story.md](Story.md)を正本とする。開始前に世界設定・導入・進行、終端でエンディング・映像化を読む。名前はメイを仮採用し、再開時はそのプレイの名前と設定を維持する。

## パスの基準

読み込んだこの `SKILL.md` の親フォルダをスキルルートとする。`scripts/`・`assets/`・`references/` は必ずスキルルートから解決し、作業フォルダからの相対パスと解釈しない。実行時に作業フォルダをスキル配下へ変更しない。`runs/call-to-past/` は現在の作業フォルダを基準とし、既存プレイはその保存先を指定して再開する。

## 開始・再開

1. [cli.md](references/cli.md)を読み、`scripts/game.py`でliveセッションを作る。既存プレイの再開ではそのセッションのcontextと初回画像記録を読む。保存先は現在の作業フォルダの`runs/call-to-past/`。スキル配下へ実写真・プレイ履歴を保存しない。
2. `start`が返した公開contextで場面と最初のギミックの選出完了を確認したら、最初の入力を待つ前に[画像手順](references/media.md)の「初回状況画像」に従う。公開contextだけから画像を実生成し、閲覧・検査・保存する。全マスター、後続ギミック、`hints`は画像生成へ渡さない。生成と表示は攻略行動に数えない。再開時は記録の状態に従って未完了の生成または一度だけの表示を完了し、すでに攻略が始まった旧セッションへ未行動状態の画像を新規追加しない。
3. 次の導入に続けて、最初の入力待ちまでに、全3障害、攻略行動は最大4回、1回写真2枚まで、持越品だけなら写真なしでも1回消費する、と短く説明する。写真のコピー・生成物・履歴はローカル保持し自動削除しないことを伝える。
4. Story.mdの導入に沿って、誰が・いつから・なぜ電話したかと写真で協力する方法を語る。公開contextから今見える空間と現在の障害1つを提示し、初回状況画像を表示する。最初だけ用途と道具例を一つ添えてよい。最初に全障害を列挙したり、導入例に合わせてロープを追加したりしない。近くの物の写真と「どう使うか」を受け取るまで待つ。現実で割る・燃やす等の操作を求めない。

写真添付にローカルパスが付く環境では、そのパスをprepareへ渡す。パスのない添付しか取得できない場合は、同じ写真を作業フォルダへ保存してファイルを指定してもらう。添付の内部パスを推測したり、表示画像から別物を描き直して原本コピーと称したりしない。実プレイ前にファイルを閲覧できることを確認する。

## 攻略行動

語りは解除数0/1/2に応じて手探り→近くの気配→遠ざかる足音を見計らう緊張へ移す。返信時間や静かさで新しい失敗条件を足さず、音が必要な攻略も確定ルールに沿って扱う。

- 質問やヒントは行動に数えない。ヒントは観察→用途→具体例の3段階で、現在の障害だけから出す。
- 写真0〜2枚、使用意図、使用する持越品ID、組み合わせの有無を特定する。0枚は持越品使用時のみ。写真内の使用対象が不明なら確認し、不鮮明ならまだ確定しない。
- `prepare`で一意の行動を作り、[判定手順](references/judging.md)と[JSON契約](references/judgment-schema.md)に従い写真認識とSol high判定を分ける。現在の障害だけを判定する。未来の全シナリオを判定担当へ渡さない。
- 検証した判定を`commit`で一度だけ反映。コードの結果を正本にして、成功を先に約束したり、会話だけで回数・在庫・結末を変更したりしない。失敗した行動でも具現化物は残り、消費・破損・合成した部品の状態は引き継がれる。
- [画像手順](references/media.md)に従い、API経路では送信前に無課金のローカルpreflightを通す。APIキー・依存関係・通信・応答回収などで画像を得られなければ、同じイベントの描画packetと参照画像でCodex内蔵image_genへ自動で切り替える。再確認やAPIログ確認を切替の前提にせず、そのプレイ中は内蔵生成を継続する。結果画像を実生成して添付し、2枚別々なら両方、合成指定なら合成した状態を描く。画像失敗を新しい攻略行動として再確定しない。
- 画像を表示し、判定理由・解除数・残り行動・使える道具を短く伝える。続けて終了状態を確認し、未終了なら必ず現在取り組むギミックを名前と観察内容つきで提示する。成功時は新しいcontextの次のギミック、失敗時は継続中の同じギミックを提示してから、次の写真と使用指示を待つ。終端なら新しいギミックを提示せずエンディングへ進む。

## 終了と再開

脚本の仕上げでは、画像生成・物語登録の前に[映画好きギャルによる独立脚本レビュー](references/ending-audience-review.md)を別エージェントへ依頼し、感想を受けて構成を見直す。自己レビューと既存の演出設計も維持する。

脚本・動画プロンプトを作る前に、[ending.mdのH3用演出設計](references/ending.md#h3用の演出設計と最終プロンプト)から撮影技法・生成担当指示・経路別記入例・文字演出資料を読む。[行動と演技から起承転結を作る](references/ending.md#行動と演技から起承転結を作る)に従い、直近2行動を起点に、両方をつなぐ案・1行動に絞る案・結果への反応から始める案を比較し、人物の目的・動作・反応を設計する。その演技を見せるカメラ・編集・同期音を選び、開始・終了画像と最終動画プロンプトまで反映する。

全解除または4行動で終了。[物語手順](references/ending.md)に従い、最後のシーンで脱出成否が分かり、未脱出なら理由も分かる映像を設計する。それまでは結果を確定させる表現を避けて緊張を保つ。カット数・時間配分は自由。人物と道具の位置・支持・動き・カメラを文章で確認する。新規・再開・別版の新しい生成は開始画像とタイトル入り終了画像を使う。最後のゲーム画像と確定履歴を両画像の根拠にし、画面に登場する道具・人物・空間の連続性を確認する。出口は必須の被写体ではなく、映す場合に既存の見た目を引き継ぐ。ゲーム中の絵コンテ画像は生成しない。座標モデルや配置図を作る工程はない。通常プレイは完成画面をattach-endingで登録し、同じ画像をH3の終了画像として送る。承認済みの旧1画像runは入力を変えず回収できる。音は効果音と環境音のみ。セリフ・ナレーション・歌・BGMを入れない。結末の根拠を示した後、終了画像に描いた確定結果のエンドタイトルへ到達するよう、登場演出とVFXをH3に指定する。指定文字以外の追加字幕は入れない。画像生成前に、この3観点で映像設計を一度以上レビューし、修正と再確認を記録する。レビュー後に画像と動画プロンプトを作り、[H3手順](references/h3-cli.md)で15秒動画へ進む。具体的な外部生成の承認は、実素材・プロンプト・最新見積を揃えて最後に得る。

生成後の映像・音声の確認は人が担当し、こちらは回収・ファイル照合と提示まで行う。動画をユーザーに表示した後で`mark-video-shown`と`result`を使い、エンド種別・タイトル・解除数・行動数・工夫へのコメントを表示する。成功数3/2/1以下の種別はコードが決める。最後に同じ設定で再挑戦するか、別の設定で遊ぶかを案内する。

画像APIの失敗は同じevent IDの内蔵生成へ切り替え、元のAPI request ID・送信状態・予約ファイルを保持する。課金の曖昧失敗で元APIへ再送しない。動画の失敗は保存済みrequest IDから再開し、画像の切替を動画APIの再送許可と解釈しない。内蔵生成も利用不能なら未完了として止め、利用者が明示的に文章版を希望した場合のみメディアをwaiveする。標準プレイで勝手に省略しない。

## 実行環境と表示上の約束

- Python3.10+、Pillow、OpenAI Python SDKを `uv run --with "openai>=2.26,<3" --with "pillow>=11,<13"` で用意し、`scripts/flare_image.py` から `gpt-image-2.5-flare` を利用する。SDKを常設環境へインストールする必要はない。APIキーは環境変数または利用者指定の資格情報ファイルから読み、値を表示・保存しない。
- 判定サブエージェントは`gpt-5.6-sol`、`high`、会話履歴を引き継がない入力で起動する。利用できない場合はその事実を伝え、モデルを偽らない。
- H3 Max Turbo I2Vの見積・一度だけの送信・回収機能は本スキルに同梱する。別途`h3-video`スキルは不要。実行環境にはfal_client、ffprobe、FAL_KEYが必要。キーは環境または利用者指定のローカル資格情報ファイルから読み、値をチャット・ログ・配布物に含めない。
- state.jsonやmasters.json全体はプレイヤーへ表示しない。プレイヤー用はcontext、画像用はイベントpacket、物語用はending-packetを使い分ける。
- リハーサル・形式テストは実写真/実生成の成功と区別する。写真の再送を新規行動にする意図がない限り、同一イベントを再利用する。
